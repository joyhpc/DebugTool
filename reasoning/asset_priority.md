# Asset Priority

Use assets in this order unless current observations contradict them:

1. Safety rules
2. User-provided current project context
3. Retrieved project facts with source/revision confidence
4. Link models / causal models
5. Authoritative-source constraints
6. Assumed link model / classic architecture when context debt is high
7. Debug principles that generalize across domains
8. Signatures for strong fast-path symptoms
9. Pattern bundles from articles/forums/app notes
10. Case records from retrospectives
11. LLM engineering reasoning

Important rule:

Case records and signatures accelerate prioritization, but they are not the foundation.  
Current observations and prerequisite link stages override past experience.

Pattern bundles and debug principles should shape questions and ordering, not override direct measurements.
